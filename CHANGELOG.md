# Changelog

## 0.5.0 — 2026-11-20

A General row at the top of the month view, listing your calendar events week by week. The month view has shown the projects since 0.4.0, but the top row of a weekly table is usually everything that is not a project — a class, a trip, a day off — and until now that row had to be copied out of Google or Apple Calendar by hand every week. The dashboard now reads the calendars you point it at and writes their events into the same weeks as the tasks: `11/6（五）13:30 讀書會`, `11/11（三）休假`, `11/7（六）–11/9（一）研習營`. Each event begins with a label showing its calendar's name in that calendar's color. An unnamed calendar uses `行事曆 1`, `行事曆 2`, … by its position in the settings list. Repeating events are expanded into single occurrences, the calendar's own exceptions and moved occurrences are respected, cancelled events are not shown, and an event over several days is listed in every week it touches. The row is read-only — its cells open no popover — and the year view shows no events. Events are read at exactly five moments: when a dashboard tab opens, when you press the `↻` in the row, when you run the new command `Refresh calendars`, when you paste a new link for a calendar that was already set up (it is read again right away), and when the list of calendars with a link, or their order, changes in the settings. This last check uses only the link settings. Renaming a calendar or changing its color updates the labels after saving, without reading events again. Moving between months never reads anything. The status line under `General` says `讀取中…` while a read is running and `更新於 15:20` afterwards, and when a calendar cannot be read it adds `・⚠ 1 個行事曆讀不到` and names the calendar and the reason in its tooltip, while every other calendar — and every project row — carries on as before.

To set it up, go to **Settings → Project Dashboard → Calendars**, the new fourth section. Press `Add a calendar`, give the calendar a name (Chinese is fine), and paste its link into the link field. The plugin saves it for you and clears the field. You can choose a label color with the `Color` picker. Until you choose one, the colors follow the list order: blue, green, orange, purple, teal, pink, then repeat. The defaults avoid red, which is reserved for overdue tasks and work beyond a project's expected end. A hint tells you whether the link is saved or still missing on this computer; a link that does not start with `https://` or `webcal://` shows an explanation below the row and is not saved. `Delete` removes the calendar and clears the link the plugin saved for it. In Google Calendar, copy **Secret address in iCal format** from the calendar's settings. For iCloud, copy the public calendar link; anyone who has it can read the calendar. Links are kept in Obsidian's secret storage, outside the settings that Obsidian Sync carries, because a calendar link can act as a read password. If a second computer says `這台裝置找不到連結`, paste the link into that calendar's link field there too. If a Google address leaks, reset it in Google Calendar and paste the new one into the link field.

With this release the plugin uses the network, which it never did before, and only for this one purpose: it requests the calendar addresses you stored yourself, with `GET`, at the five moments above. It never writes to a calendar and sends no note, setting, or other vault content anywhere. Fetched events stay in memory and are discarded when the plugin unloads. When no calendar is set up, no request is made at all.

Reading iCalendar files and expanding repeating rules is done by [ical.js](https://github.com/kewisch/ical.js), which is now bundled unmodified in `main.js` under the MPL-2.0; the comment at the top of `main.js` names the library, its license, and its source address. `main.js` therefore grows from about 62 KB to about 150 KB.

You can now plan next year in the year view. Use `◀` and `▶` beside the year title to move between years, in the same place as the month controls. `今年` appears only when you are looking at another year; `本月` now appears only when you are looking at another month. Switching from another year to the month view opens January of that year; switching from this year opens the month of today's week. Switching from a month to the year view shows that month's year. Opening the dashboard starts on this year or the month of today's week; the shown year and month are not remembered. Cross-year projects also display correctly: if a project's expected end was in an earlier year but its tasks continue into the shown year, its overflow weeks still appear red in the per-week view, and its timeline bar starts at the shown year's first week. This case was easy to miss while the year view only showed this year; it becomes common when planning next year. Projects with no end date still default to December 31 of today's year, whatever year is shown.

Fixed: clicking a year-view week cell, a month-view cell, or a `還沒排` cell now opens its popover after you move the dashboard tab into a pop-out window. Click and scroll handling previously stayed in the main window; it now follows the window containing the tab, so scrolling there closes the popover as before. Category legend dragging and project column resizing follow that window too.

Paused projects used to stay among active work, making it harder to see what needs attention. They are now hidden by default in both the year and month views. `顯示暫停（<n>）` appears when there are paused projects to show, updates its count after each scan, and reveals them with a grey `⏳ 暫停` badge after the name and diagonal stripes in the category color on year-view bars and month-view cells when checked. `編輯分類與狀態` now reveals a status menu alongside each category menu, so you can pause, resume, complete, or cancel a project while planning. Changing status renames the note's leading symbol in the same folder and keeps your manual category choice; links from other notes follow Obsidian's automatically-update-internal-links setting. An existing note with the target name prevents the change and shows a message.

Security fixes: a malformed repeating event could keep searching for a date forever, so it now stops without blocking Obsidian or hiding other events. Calendar responses over 20 MB are rejected, and calendar time zones no longer keep entire calendars in memory after unloading. Pasting a link now replaces only a link created by this plugin, preserving secrets used elsewhere; the field hides pasted text and clears rejected links. Long spaces in a task no longer slow down unticking it, and examples inside longer code fences stay protected from edits. Unloading saves any pending settings once and stops later saves.

Dated tasks now always appear in their own week and can be opened in both views. Previously, a task outside the project's expected date range could disappear: a project expected to end on 11/6 could still have two tasks on 12/5, yet both views showed a blank week. With Saturday tasks counted in the following week, the example dated `2026-12-05` now appears in `2026-W50`. The expected end only decides whether an active or paused project's task week is red. It is an estimate, so getting it wrong should not hide real work. Tasks before the start also stay visible, and closed projects keep later tasks in grey when shown. A date mistake in one project, such as an end in 9999, no longer prevents the rest of the chart from appearing. If one row cannot be drawn, only that row has empty week cells and `⚠`; the other rows still appear.

The `?` help panel now has three tabs: `年視圖`, `月視圖`, and `操作`. It opens on the tab for the current view. As more features were added, the old single long list became hard to read. Each tab now groups its short lines by topics such as what a cell means, what a whole row means, colors and columns, and things needing attention. Each visual item has a small sample matching the chart, including paused rows, calendar name labels, and `還沒排` counts.

月視圖最上面新增一列 General，一週一格列出你行事曆的行程。月視圖從 0.4.0 開始就會畫出專案，但週表格最上面那一列通常是「不是專案的事情」——上課、出遊、休假——在這之前得每週從 Google 或 Apple 行事曆手抄。現在儀表板會去讀你指定的行事曆，把行程寫進和任務相同的那幾週：`11/6（五）13:30 讀書會`、`11/11（三）休假`、`11/7（六）–11/9（一）研習營`。每筆行程前面都有名稱標籤，使用那個行事曆的顏色；沒取名時，依設定清單的位置顯示 `行事曆 1`、`行事曆 2`……重複的行程會展開成一次一次的行程，行事曆自己的例外與被移動的那幾次都照算，已取消的行程不顯示，跨好幾天的行程會列在它碰到的每一週。這一列只能看——點格子不會打開浮窗——年視圖不顯示任何行程。讀取只發生在五個時機：儀表板分頁打開時、按這一列的 `↻` 時、執行新指令 `Refresh calendars` 時、在已設好的行事曆貼上新連結時（會馬上重新讀取），以及在設定裡改動設定過連結的行事曆清單或順序時。最後這項比對只看連結設定。改名或換色存檔後，標籤就會更新，不會重新讀取行程。在月份之間移動永遠不會去讀。`General` 下面的狀態列在讀取中寫 `讀取中…`，讀完寫 `更新於 15:20`；有行事曆讀不到時會接上 `・⚠ 1 個行事曆讀不到`，並在提示裡寫出是哪個行事曆、什麼原因，其他行事曆——以及每一列專案——都照常。

設定方式：到**設定 → Project Dashboard → Calendars**，這是新增的第四區。按 `Add a calendar`，給行事曆取個名稱（可以打中文），再把連結貼進連結欄。外掛會自動儲存並清空欄位。可以用 `Color` 選擇標籤顏色；還沒選過時，依清單順序使用藍、綠、橘、紫、青、粉，再從藍色輪流。預設色避開紅色，紅色留給逾期任務與超出專案預計結束日期的工作。提示文字會告訴你這台電腦已存好連結，或還沒有連結。貼上的內容如果不是 `https://` 或 `webcal://` 開頭，就不會儲存，並在該列下方顯示說明。按 `Delete` 會移除行事曆，也清空外掛替它存的連結。在 Google 日曆，到該日曆的設定複製 **iCal 格式的私密網址**；使用 iCloud 時，複製公開行事曆的連結，任何人拿到都看得到。連結存在 Obsidian 的密鑰儲存區，不會進入 Obsidian Sync 同步的設定裡，因為行事曆連結可能等於讀取密碼。如果第二台電腦顯示 `這台裝置找不到連結`，在那台同一個行事曆的連結欄也貼上即可。Google 網址萬一外洩，到 Google 日曆重設，再把新網址貼進連結欄。

這一版開始，外掛會連網——以前完全不連——而且只為了這一件事：用 `GET` 請求你自己存進去的行事曆網址，只在上面那五個時機。它絕不寫入行事曆，也不會把筆記、設定或任何 vault 內容送到任何地方。讀回來的行程只放在記憶體，外掛卸載就丟掉。沒有設定任何行事曆時，完全不發請求。

讀 iCalendar 檔案與展開重複規則是 [ical.js](https://github.com/kewisch/ical.js) 做的，它現在原封不動打包進 `main.js`，採 MPL-2.0 授權；`main.js` 開頭的註解寫出這個套件、它的授權與原始碼位置。因此 `main.js` 從約 62 KB 變成約 150 KB。

現在可以在年視圖開始排明年了。在年份標題旁按 `◀`、`▶` 切換年份，位置和月視圖的導覽相同。翻到別的年份才會出現 `今年`；`本月` 也改成翻到別的月份才出現。在別的年份切到月視圖，會顯示那一年的一月；在今年切換，會顯示今天這週所屬的月份。月視圖切回年視圖，會顯示那個月所在的年份。打開儀表板時，從今年或今天這週所屬的月份開始，不記住上次看的年份與月份。跨年專案也修正了：預計結束日期在前一年，任務卻延伸到顯示中的這一年時，逐週模式仍會把超出期限的週標紅，timeline 色條則從這一年的第一週開始。以前年視圖只看今年，這個情況很少碰到；開始排明年後就容易遇到。沒有結束日期的專案，預設結束日仍是今天所在年份的 12/31，不會跟著顯示的年份改變。

修正：把儀表板分頁拖到獨立視窗後，點年視圖週格子、月視圖格子或「還沒排」格子，現在都能打開浮窗。原本點擊與捲動的監聽留在主視窗，現在會跟著分頁所在的視窗，因此在獨立視窗裡捲動時，浮窗也會照原本規則關閉。圖例拖拉排序與專案欄寬拖拉也會跟著分頁所在的視窗運作。

暫停的專案以前仍混在進行中的工作裡，讓人難以看出現在該推進什麼。現在年視圖與月視圖都會預設隱藏暫停專案。有暫停專案可顯示時，控制列才會出現 `顯示暫停（<n>）`，每次重新掃描都更新數量；勾起來後，名稱後面有灰色的 `⏳ 暫停` 標籤，年視圖色條與月視圖格子則以分類色斜線紋呈現。勾選 `編輯分類與狀態`，每列分類選單旁會出現狀態選單，規劃時就能暫停、恢復進行、完成或取消專案。改狀態會替換筆記檔名開頭的符號，保留所在資料夾與手動指定的分類；其他筆記的連結是否更新，依 Obsidian 的「自動更新內部連結」設定處理。如果已經有同名筆記，就不會改名並顯示提示。

資安修正：寫壞的重複行程原本可能一直尋找不存在的日期，讓 Obsidian 卡住；現在會停止尋找，其他行程仍照常顯示。超過 20 MB 的行事曆會停止讀取，卸載後也不再因時區資料而留住整份行事曆。貼新連結時只會覆寫外掛自己存的連結，保留其他用途的密鑰；輸入欄會遮住文字，貼錯時清空並顯示原因。任務裡很長的空白不再拖慢取消勾選，較長程式碼圍欄裡的範例任務也不會被誤改。卸載時會把尚未儲存的設定存一次，之後不再存檔。

有日期的任務現在一律出現在它那一週，年視圖與月視圖都能點開。以前任務超出專案預計日期範圍時可能消失：例如預計 11/6 結束的專案，還有兩個 12/5 的任務，兩個視圖卻都顯示空白。開著週六算到下一週時，範例的 `2026-12-05` 任務現在會出現在 `2026-W50`。預計結束日期只決定進行中或暫停專案的任務週要不要標紅色。日期本來就是預估，估不準時不該讓真實任務消失。開始日期之前的任務也會顯示，已結案專案的後續任務在顯示時保留灰色。單一專案日期寫壞，例如結束日期寫成 9999 年，也不會再讓整張圖畫不出來。如果某列無法顯示，只有那列的週格子留白並加上 `⚠`，其他列照畫。

右下角 `?` 的說明面板改成 `年視圖`、`月視圖`、`操作` 三個分頁。在哪個視圖打開，就先顯示哪個分頁。功能增加後，原本一長串清單擠在一起很難讀。現在各分頁依一格的意思、整列的意思、顏色與欄位、需要注意的事項等主題分組，每行保持簡短。每個視覺項目左邊都有和畫面相同的小示範，也補上暫停列、行事曆名稱標籤與 `還沒排` 數字。

## 0.4.0 — 2026-10-31

A month view. The controls row has a `年` / `月` switch, and `M` toggles between the two; `◀`, `▶`, and `本月` move between months, and the title reads `2026 年 10 月（W41–W44）`. Where the year view draws a colored cell per week, the month view shows one month at a time and writes the week's tasks into the cell, which is what weekly planning needs: a done task shows `✓` in grey, a task whose week is already over and is still not done shows in red, everything else in normal text. A cell's background follows the same cell kind as the year view, and a cell outside the project's range stays blank and lists nothing. Clicking a cell opens the same week popover as the year view, anchored on that cell, so a week can be edited right where it is read — this works even when the year view was left in timeline mode, because timeline mode and the `T` shortcut apply to the year view only. A last column, `還沒排`, counts the project's tasks that have no date yet; clicking the count opens the same popover with those tasks listed, each with one button per week of the shown month, so an undated task goes straight into a week — the date written is the one the week popover would write, and weeks outside the project's range are greyed out. The month view always opens on the month of today's week; only the year-versus-month choice is remembered, not the month you were last looking at.

The year view's month and quarter headers changed with it. A week now belongs to the month its Monday falls in, the same rule the month view uses and the same way a weekly table is filled in — by the week's Monday — so the two views can never disagree about which month a week is in. Week 1 is the one exception and still counts as January, even though its Monday is in December. **In 2026 exactly five weeks therefore move one month earlier than 0.3.0 showed them: W14, W27, W36, W40, and W49.** W40, for example, starts on 9/28 and now sits under 9 月 instead of 10 月. Three of those five also move one quarter earlier: W14 from Q2 to Q1, W27 from Q3 to Q2, and W40 from Q4 to Q3. Nothing else about the year view changes — every ISO week still has its own column, and every cell, tooltip, and popover shows what it showed before.

新增月視圖。控制列有一組 `年` / `月` 切換，按 `M` 也能切換；`◀`、`▶`、`本月` 可以切換月份，標題寫成 `2026 年 10 月（W41–W44）`。年視圖一週畫一個色塊，月視圖則一次顯示一個月，把那一週的任務直接寫進格子裡，這才是每週規劃需要的樣子：已完成的任務是灰字加 `✓`，那一週已經過了還沒完成的任務是紅字，其他是一般文字。格子的底色跟年視圖同一週的格子種類一致，不在專案區間的格子留白、不列任何任務。點格子會打開年視圖的那個週浮窗，錨點就在那一格，看到哪一週就能當場編輯——年視圖存在 timeline 模式時也一樣，因為 timeline 模式和 `T` 快捷鍵只作用在年視圖。最後一欄 `還沒排` 算出這個專案還有幾個任務沒有日期；點那個數字會打開同一個浮窗列出它們，每一列有顯示中那個月每一週一顆按鈕，可以直接把還沒排的任務排進某一週——寫進筆記的日期和週浮窗寫的一樣，不在專案期間的那幾週按鈕是灰的。月視圖永遠從今天這週所屬的月份開始；只有「年或月」會被記住，上次看的是哪個月不會。

年視圖的月份與季度表頭跟著改。現在一週屬於它星期一落在的那個月，和月視圖用同一條規則，也和填週表格的方式一樣——照那一週的星期一——所以兩個視圖對「某一週屬於哪個月」不可能講不一樣。第 1 週是唯一的例外，仍然算一月，即使它的星期一在 12 月。**因此 2026 年剛好有五週比 0.3.0 顯示的位置往前一個月：W14、W27、W36、W40、W49。**例如 W40 起於 9/28，現在排在 9 月，不再是 10 月。這五週裡有三週也往前一季：W14 從 Q2 變 Q1、W27 從 Q3 變 Q2、W40 從 Q4 變 Q3。年視圖其他部分都沒變——每個 ISO 週還是各有一欄，每個格子、提示文字與浮窗顯示的內容都和以前相同。

## 0.3.0 — 2026-10-30

A settings tab. Everything that used to be compiled into the plugin — the project folder, the classification keywords, the manual name fragments, the excluded projects — is now set under **Settings → Project Dashboard** and stored in the vault's plugin data, next to the category choices you make by hand on the dashboard. Until now those rules were read at build time from a git-ignored source file, so anyone installing the release files could only use the folder `Projects` and the example keywords, and changing a single keyword meant editing source and rebuilding `main.js`. Personal rules therefore need no rebuild any more, and the release `main.js` no longer differs depending on the machine it was built on. Changes are saved 400 ms after your last edit and an open dashboard re-scans and re-renders on its own, without being reopened. Because the settings live in plugin data, Obsidian Sync carries them: settings changed on another device are reloaded and redrawn here, and they win over a local edit that has not been saved yet.

The manual name fragments and the keyword rules became one ordered rule list. Both meant the same thing — a project whose name contains this text belongs to this category — and differed only in which set was matched first, which made two identical-looking tables in the settings tab and one more thing to remember. The tab now shows a single list, matched from top to bottom, first match wins, with `Move up` / `Move down` / `Delete` on each row. Existing setups keep the old priority by putting the manual fragments above the keywords, so classification results are unchanged. A category picked by hand on a project row still wins over every rule.

The Saturday rule is now a setting, and it is OFF by default, because counting Saturday dates as the next week is one person's planning habit rather than general behaviour. In 0.2.0 a task dated on a Saturday was always moved to the following week; with the setting off it now stays in its own week, on the chart, in the tooltip, and in the week popover. **If you relied on Saturday dates counting as the next week, turn on `Saturday tasks count for next week` in the settings tab.** The schedule weekday is configurable too: `Which day to write` chooses the day written when you schedule a task into a week from the popover, and defaults to `Friday`, the value 0.2.0 had fixed in code. Choosing `Saturday` while the Saturday rule is on writes the Saturday before that week's Monday, so the task still shows in the week you picked instead of jumping forward one week.

Before upgrading, back up `.obsidian/plugins/project-dashboard/data.json` and update every computer that syncs the vault to 0.3.0 together. 0.2.0 knows nothing about the `settings` key, and each write of plugin data replaces the whole file: the moment an older install saves a manual category, it writes plugin data containing only `categoryOverrides`, which deletes all your settings, and Obsidian Sync then carries that truncated file to every device. Keep the plugin disabled on the computers you have not updated yet.

新增設定頁。原本編進程式裡的 `Project folder`（專案資料夾）、分類關鍵字與手動分類片段（現在的 `Categories`）、`Projects to skip`（不列入的專案），現在都在**設定 → Project Dashboard** 設定，存進 vault 裡的外掛資料，和你在儀表板上手動指定的分類放在同一份。在這之前，這些規則是建置時從一個 git 忽略的程式檔讀進來的，所以下載 release 檔案安裝的人只能用 `Projects` 資料夾和範例關鍵字，改一個關鍵字都得改原始碼、重新建置 `main.js`。因此個人規則不再需要重新建置，release 的 `main.js` 也不會再因為在哪台電腦建置而內容不同。修改會在最後一次改動後 400 ms 存檔，開著的儀表板自己重新掃描、重繪，不必關掉重開。設定放在外掛資料裡，Obsidian Sync 會一起同步：在其他裝置改的設定同步過來時會重新載入並重繪，而且蓋過本機還沒存起來的修改。

手動分類片段與分類關鍵字合併成一份有順序的規則清單。兩者的意思本來就相同——專案名稱包含某段文字就歸到某個分類——差別只在誰先比對，結果是設定頁會出現兩張長得一樣的表格，還多一件要記的事。現在只有一份清單，由上往下比對，第一個符合的生效，每一列都有 `Move up`（上移）、`Move down`（下移）、`Delete`（刪除）。既有設定搬過來時，手動片段排在關鍵字前面，維持原本的優先順序，所以分類結果不變。在專案列上手動指定的分類，仍然優先於所有規則。

週六規則改成設定，而且預設關閉，因為「週六的日期算到下一週」是個人的排程習慣，對其他人不一定成立。0.2.0 的週六任務一律移到下一週；設定關閉時，週六的任務留在當週，年視圖格子、提示文字與週浮窗都一致。**原本依賴週六算下一週的人，請到設定頁打開 `Saturday tasks count for next week`（週六的任務算到下一週）。**排程的星期幾也能設定：`Which day to write`（排進某週時寫星期幾）決定從浮窗把任務排進某一週時寫哪一天，預設 `Friday`（星期五），也就是 0.2.0 寫死在程式裡的那一天。選 `Saturday` 又開著週六規則時，寫的是那週星期一前面的那個星期六，所以任務仍然顯示在你挑的那一週，不會往後跳一週。

升級前，先備份 `.obsidian/plugins/project-dashboard/data.json`，並且讓所有會同步這個 vault 的電腦一起更新到 0.3.0。0.2.0 不認識 `settings` 這個欄位，而每次寫入外掛資料都是整份覆蓋：舊版只要存一次手動分類，就會寫入只有 `categoryOverrides` 的外掛資料，把你的設定整段刪掉，Obsidian Sync 接著把這份被刪掉設定的檔案傳到每一台裝置。還沒更新的電腦，請先停用本外掛。

## 0.2.0 — 2026-10-26

Edit tasks from the week popover. Clicking a week cell in the per-week view now opens a task list for that week: tick a task done or undo it, move it a week earlier or later with `◀` / `▶`, put one of the note's undated tasks into the week, add a new task, or jump to the task's line with `↗`. Clicking the project name at the top of the popover opens the note beside the dashboard. Empty dashed weeks and the dashed bar of a project without task dates open it too, so you can schedule the first task of an empty week. Changes are written into the project note in the Tasks plugin's emoji format; scheduled and new tasks get that week's Friday. Before saving, the dashboard checks that the line still matches what it last read, and asks you to try again if the note changed in between, so it never overwrites what you just typed. The popover stays open across the automatic refresh that follows each edit, and the new-task input stays open so several tasks can be added in a row. Lines inside code blocks or the frontmatter are never edited.

Fixed: a task line was counted as done whenever it contained a `✅` anywhere, so a task that merely linked to a finished note (`[[✅ …]]`) made its week look settled. A task now counts as done only when its checkbox is ticked or it carries a `✅` followed by a date, which is the marker the Tasks plugin writes.

Fixed: the week popover was cut off while the left sidebar was open, and cells near the right edge seemed to do nothing while a note was open in a split, because the popover was clipped inside the dashboard tab. It now floats above the whole window and stays inside the dashboard pane whenever it fits.

在週浮窗裡編輯任務。逐週模式下點週格子，會打開那一週的任務清單：可以勾完成或取消、用 `◀` `▶` 把任務移到前一週或下一週、把筆記裡還沒排日期的任務排進這週、新增任務，或按 `↗` 跳到筆記那一行。點浮窗最上方的專案名稱，會在儀表板右側打開這則筆記。空的虛線週與沒有任務日期的整條虛線也能點，所以可以把第一個任務排進空的那週。改動直接寫回專案筆記，用 Tasks 外掛的 emoji 格式；排進某週與新增的任務寫那週的星期五。寫入前會確認那一行跟儀表板上次讀到的一樣，筆記剛好被改過就不寫，請你再按一次，所以不會蓋掉你剛打的字。每次改完畫面自動更新時，浮窗會留在原本那一週，新增任務的輸入框也會保持開著，可以連續新增。程式碼區塊與 frontmatter 裡的行不會被修改。
