# Changelog

## 0.4.0 — 2026-10-31

A month view. The controls row has a `年` / `月` switch, and `M` toggles between the two; `◀`, `▶`, and `本月` move between months, and the title reads `2026 年 10 月（W41–W44）`. Where the year view draws a colored cell per week, the month view shows one month at a time and writes the week's tasks into the cell, which is what weekly planning needs: a done task shows `✓` in grey, a task whose week is already over and is still not done shows in red, everything else in normal text. A cell's background follows the same cell kind as the year view, and a cell outside the project's range stays blank and lists nothing. Clicking a cell opens the same week popover as the year view, anchored on that cell, so a week can be edited right where it is read — this works even when the year view was left in timeline mode, because timeline mode and the `T` shortcut apply to the year view only. A last column, `還沒排`, counts the project's tasks that have no date yet and lists them in its tooltip. The month view always opens on the month of today's week; only the year-versus-month choice is remembered, not the month you were last looking at.

The year view's month and quarter headers changed with it. A week now belongs to the month its Monday falls in, the same rule the month view uses and the same way a weekly table is filled in — by the week's Monday — so the two views can never disagree about which month a week is in. Week 1 is the one exception and still counts as January, even though its Monday is in December. **In 2026 exactly five weeks therefore move one month earlier than 0.3.0 showed them: W14, W27, W36, W40, and W49.** W40, for example, starts on 9/28 and now sits under 9 月 instead of 10 月. Three of those five also move one quarter earlier: W14 from Q2 to Q1, W27 from Q3 to Q2, and W40 from Q4 to Q3. Nothing else about the year view changes — every ISO week still has its own column, and every cell, tooltip, and popover shows what it showed before.

新增月視圖。控制列有一組 `年` / `月` 切換，按 `M` 也能切換；`◀`、`▶`、`本月` 可以切換月份，標題寫成 `2026 年 10 月（W41–W44）`。年視圖一週畫一個色塊，月視圖則一次顯示一個月，把那一週的任務直接寫進格子裡，這才是每週規劃需要的樣子：已完成的任務是灰字加 `✓`，那一週已經過了還沒完成的任務是紅字，其他是一般文字。格子的底色跟年視圖同一週的格子種類一致，不在專案區間的格子留白、不列任何任務。點格子會打開年視圖的那個週浮窗，錨點就在那一格，看到哪一週就能當場編輯——年視圖存在 timeline 模式時也一樣，因為 timeline 模式和 `T` 快捷鍵只作用在年視圖。最後一欄 `還沒排` 算出這個專案還有幾個任務沒有日期，滑過去的提示會列出它們。月視圖永遠從今天這週所屬的月份開始；只有「年或月」會被記住，上次看的是哪個月不會。

年視圖的月份與季度表頭跟著改。現在一週屬於它星期一落在的那個月，和月視圖用同一條規則，也和填週表格的方式一樣——照那一週的星期一——所以兩個視圖對「某一週屬於哪個月」不可能講不一樣。第 1 週是唯一的例外，仍然算一月，即使它的星期一在 12 月。**因此 2026 年剛好有五週比 0.3.0 顯示的位置往前一個月：W14、W27、W36、W40、W49。**例如 W40 起於 9/28，現在排在 9 月，不再是 10 月。這五週裡有三週也往前一季：W14 從 Q2 變 Q1、W27 從 Q3 變 Q2、W40 從 Q4 變 Q3。年視圖其他部分都沒變——每個 ISO 週還是各有一欄，每個格子、提示文字與浮窗顯示的內容都和以前相同。

## 0.3.0 — 2026-10-30

A settings tab. Everything that used to be compiled into the plugin — the project folder, the classification keywords, the manual name fragments, the excluded projects — is now set under **Settings → Project Dashboard** and stored in the vault's plugin data, next to the category choices you make by hand on the dashboard. Until now those rules were read at build time from a git-ignored source file, so anyone installing the release files could only use the folder `Projects` and the example keywords, and changing a single keyword meant editing source and rebuilding `main.js`. Personal rules therefore need no rebuild any more, and the release `main.js` no longer differs depending on the machine it was built on. Changes are saved 400 ms after your last edit and an open dashboard re-scans and re-renders on its own, without being reopened. Because the settings live in plugin data, Obsidian Sync carries them: settings changed on another device are reloaded and redrawn here, and they win over a local edit that has not been saved yet.

The manual name fragments and the keyword rules became one ordered rule list. Both meant the same thing — a project whose name contains this text belongs to this category — and differed only in which set was matched first, which made two identical-looking tables in the settings tab and one more thing to remember. The tab now shows a single list, matched from top to bottom, first match wins, with `Move up` / `Move down` / `Delete` on each row. Existing setups keep the old priority by putting the manual fragments above the keywords, so classification results are unchanged. A category picked by hand on a project row still wins over every rule.

The Saturday rule is now a setting, and it is OFF by default, because counting Saturday dates as the next week is one person's planning habit rather than general behaviour. In 0.2.0 a task dated on a Saturday was always moved to the following week; with the setting off it now stays in its own week, on the chart, in the tooltip, and in the week popover. **If you relied on Saturday dates counting as the next week, turn on `Saturday tasks count for next week` in the settings tab.** The schedule weekday is configurable too: `Which day to write` chooses the day written when you schedule a task into a week from the popover, and defaults to `Friday`, the value 0.2.0 had fixed in code. Choosing `Saturday` while the Saturday rule is on writes the Saturday before that week's Monday, so the task still shows in the week you picked instead of jumping forward one week.

Before upgrading, back up `.obsidian/plugins/project-dashboard/data.json` and update every computer that syncs the vault to 0.3.0 together. 0.2.0 knows nothing about the `settings` key, and each write of plugin data replaces the whole file: the moment an older install saves a manual category, it writes plugin data containing only `categoryOverrides`, which deletes all your settings, and Obsidian Sync then carries that truncated file to every device. Keep the plugin disabled on the computers you have not updated yet.

新增設定頁。原本編進程式裡的 `Project folder`（專案資料夾）、分類關鍵字與手動分類片段（現在的 `Categories`）、`Projects to skip`（不列入的專案），現在都在**設定 → Project Dashboard** 設定，存進 vault 裡的外掛資料，和你在儀表板上手動指定的分類放在同一份。在這之前，這些規則是建置時從一個 git 忽略的程式檔讀進來的，所以下載 release 檔案安裝的人只能用 `Projects` 資料夾和範例關鍵字，改一個關鍵字都得改原始碼、重新建置 `main.js`。因此個人規則不再需要重新建置，release 的 `main.js` 也不會再因為在哪台電腦建置而內容不同。修改會在最後一次改動後 400 ms 存檔，開著的儀表板自己重新掃描、重繪，不必關掉重開。設定放在外掛資料裡，Obsidian Sync 會一起同步：在其他裝置改的設定同步過來時會重新載入並重繪，而且蓋過本機還沒存起來的修改。

手動分類片段與分類關鍵字合併成一份有順序的規則清單。兩者的意思本來就相同——專案名稱包含某段文字就歸到某個分類——差別只在誰先比對，結果是設定頁會出現兩張長得一樣的表格，還多一件要記的事。現在只有一份清單，由上往下比對，第一個符合的生效，每一列都有 `Move up`（上移）、`Move down`（下移）、`Delete`（刪除）。既有設定搬過來時，手動片段排在關鍵字前面，維持原本的優先順序，所以分類結果不變。在專案列上手動指定的分類，仍然優先於所有規則。

週六規則改成設定，而且預設關閉，因為「週六的日期算到下一週」是個人的排程習慣，對其他人不一定成立。0.2.0 的週六任務一律移到下一週；設定關閉時，週六的任務留在當週，年視圖格子、提示文字與週浮窗都一致。**原本依賴週六算下一週的人，請到設定頁打開 `Saturday tasks count for next week`（週六的任務算到下一週）。**排程的星期幾也能設定：`Which day to write`（排進某週時寫星期幾）決定從浮窗把任務排進某一週時寫哪一天，預設 `Friday`（星期五），也就是 0.2.0 寫死在程式裡的那一天。選 `Saturday` 又開著週六規則時，寫的是那週星期一前面的那個星期六，所以任務仍然顯示在你挑的那一週，不會往後跳一週。

升級前，先備份 `.obsidian/plugins/project-dashboard/data.json`，並且讓所有會同步這個 vault 的電腦一起更新到 0.3.0。0.2.0 不認識 `settings` 這個欄位，而每次寫入外掛資料都是整份覆蓋：舊版只要存一次手動分類，就會寫入只有 `categoryOverrides` 的外掛資料，把你的設定整段刪掉，Obsidian Sync 接著把這份被刪掉設定的檔案傳到每一台裝置。還沒更新的電腦，請先停用本外掛。

## 0.2.0 — 2026-10-26

Edit tasks from the week popover. Clicking a week cell in the per-week view now opens a task list for that week: tick a task done or undo it, move it a week earlier or later with `◀` / `▶`, put one of the note's undated tasks into the week, add a new task, or jump to the task's line with `↗`. Clicking the project name at the top of the popover opens the note beside the dashboard. Empty dashed weeks and the dashed bar of a project without task dates open it too, so you can schedule the first task of an empty week. Changes are written into the project note in the Tasks plugin's emoji format; scheduled and new tasks get that week's Friday. Before saving, the dashboard checks that the line still matches what it last read, and asks you to try again if the note changed in between, so it never overwrites what you just typed. The popover stays open across the automatic refresh that follows each edit, and the new-task input stays open so several tasks can be added in a row. Lines inside code blocks or the frontmatter are never edited.

Fixed: a task line was counted as done whenever it contained a `✅` anywhere, so a task that merely linked to a finished note (`[[✅ …]]`) made its week look settled. A task now counts as done only when its checkbox is ticked or it carries a `✅` followed by a date, which is the marker the Tasks plugin writes.

Fixed: the week popover was cut off while the left sidebar was open, and cells near the right edge seemed to do nothing while a note was open in a split, because the popover was clipped inside the dashboard tab. It now floats above the whole window and stays inside the dashboard pane whenever it fits.

在週浮窗裡編輯任務。逐週模式下點週格子，會打開那一週的任務清單：可以勾完成或取消、用 `◀` `▶` 把任務移到前一週或下一週、把筆記裡還沒排日期的任務排進這週、新增任務，或按 `↗` 跳到筆記那一行。點浮窗最上方的專案名稱，會在儀表板右側打開這則筆記。空的虛線週與沒有任務日期的整條虛線也能點，所以可以把第一個任務排進空的那週。改動直接寫回專案筆記，用 Tasks 外掛的 emoji 格式；排進某週與新增的任務寫那週的星期五。寫入前會確認那一行跟儀表板上次讀到的一樣，筆記剛好被改過就不寫，請你再按一次，所以不會蓋掉你剛打的字。每次改完畫面自動更新時，浮窗會留在原本那一週，新增任務的輸入框也會保持開著，可以連續新增。程式碼區塊與 frontmatter 裡的行不會被修改。

修正：原本只要任務那一行出現 `✅` 就算完成，所以任務文字裡連到已完成筆記的 `[[✅ …]]`，會讓那一週被畫成已完成。現在要核取方塊打勾，或 `✅` 後面接日期（Tasks 外掛寫入的完成標記）才算完成。

修正：左側邊欄打開時，週浮窗會被切掉；右側開著筆記時，點靠右的格子像是沒反應。原因是浮窗被限制在儀表板分頁裡面。現在浮窗浮在整個視窗上方，放得下時會留在儀表板範圍內。

## 0.1.0 — 2026-10-25

First public version. Project Dashboard renders a year-at-a-glance Gantt chart of project notes as an Obsidian plugin tab: scans a configured project folder, derives each project's status, category, and date range from its filename, frontmatter, and task dates, and keeps the chart in sync as notes change.
