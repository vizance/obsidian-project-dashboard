## Context

格子模型在 `src/core/cells.ts`：

- `perWeekCells` 用「傳進來那段週」裡的索引算 `startIdx`、`endIdx`、`overflowEndIdx`，決定每格是實心、settled、超出期限、虛線或空白。
- 年視圖的 `yearViewCells` 與月視圖的 `monthViewCells`，為了跨年、跨月也算對，會先補出一段蓋住專案整段期間的連續週，再在這段上算。
- `timelineCells` 用 `max(end, overflow_end)` 決定右邊界。

`overflow_end` 是原始任務日期的最大值，可是 `occupied_weeks` 照週六規則對應。所以星期六的任務若是在預計結束日期之後，會落在超出期限範圍的下一週，變成空白格。

## Goals / Non-Goals

**Goals:**

- 筆記裡每一個有日期的任務，都出現在它那一週、能打開編輯。
- 預計結束日期只決定「超出期限」的紅色標示。
- 任何日期都不會讓畫圖變慢或出錯。

**Non-Goals:**

- 改掃描欄位的定義、改週六規則、改筆記。

## Decisions

### 每一週獨立判斷種類

新增一個純函式，例如 `weekCellKind(project, week, rules)`，只看這一週與專案：

- 有任務、專案沒結案：
  - 週一在預計結束日期當天或之後：`overflow`。
  - 其他（包含開始日期之前）：`solid`；這週任務全部完成時是 `settled`。
- 有任務、專案已結案：`solid`，套用既有的結案樣式。
- 沒任務、在 `[start, end)` 期間內、沒結案：`dashed`。
- 其他：`blank`。
- 沒有任何任務日期、沒結案的專案：照舊在期間內畫成整條虛線。年視圖合成一條 `span-dashed`，起點與長度只算顯示中的週；月視圖每週一格 `dashed`。

`perWeekCells`、`yearViewCells`、`monthViewCells` 都改用它，不再補連續的週。tooltip 照舊：`overflow` 那一格的提示要寫出超出預計結束日期。

替代方案一：只修週六的落差，讓 `overflow_end` 改用對應後的週。開始日期之前、已結案之後的任務還是會被藏起來，和朱騏「預計日期只是預估」的原則不合，所以不採用。

替代方案二：保留補連續週的做法，加上長度上限。做法比較複雜，而且每週獨立判斷本來就不需要它，所以不採用。

### timeline 色條的兩端

左端取「開始日期那週」與「第一個有任務的週」較早的；右端取「預計結束日期那週」與「最後一個有任務的週」較晚的。只畫在顯示中這一年的範圍內。

### 一列出錯不影響其他列

`view.ts` 的年視圖每一列、`month-view.ts` 的月視圖每一列，各自 try/catch：
- 出錯的那一列只畫專案名稱、空白格，並加上 `⚠`，提示 `這個專案的日期有問題`。
- 錯誤寫到 console 時只寫專案名稱，不寫筆記內容。

### 真實資料比對

實作後用維護者 vault 比對新舊每一格，比對範圍是 2025、2026、2027 年的年視圖，以及 2026 年各月的月視圖。差異只能是「原本空白、現在有任務的週」。

## Implementation Contract

**行為：**
- 有任務的週一律畫出、能打開。
- 預計結束日期之後的任務週是紅色（進行中與暫停）或灰色（已結案）。
- 開始日期之前的任務週是實心。
- 9999 年的筆記 50 ms 內畫完，不影響其他列。

**介面與資料形狀：** `src/core/cells.ts` 新增每週判斷的純函式；`perWeekCells`、`yearViewCells`、`monthViewCells`、`timelineCells` 的參數不變，結果依新規則。

**失敗與錯誤處理：** 單列出錯只影響那一列，畫成名稱、空白格加 `⚠ 這個專案的日期有問題`。

**驗收標準：**
- 規格的每個情境都有測試：週六任務、開始前任務、結案後任務、月視圖兩個情境、timeline 兩端、9999 年。
- 既有測試中依舊規則寫的期待值，照新規則更新，並列出改了哪些。
- 真實資料比對的差異只有「原本空白、現在有任務的週」。
- `npm test`、`npm run lint`、`npm run build` 通過。

**範圍內：** 格子模型、timeline 兩端、單列隔離、CHANGELOG 與 README 的說明。

**範圍外：** Non-Goals 列出的所有項目。

## Risks / Trade-offs

- [以前藏起來的任務週會冒出來，朱騏可能嚇一跳] → CHANGELOG 寫明原因；真實資料比對列出所有變化，部署前先告訴朱騏。
- [開始日期之前的任務週也畫成實心，可能被誤以為專案提早開始] → 這正是「真實呈現筆記」的要求；想調整就改開始日期。
