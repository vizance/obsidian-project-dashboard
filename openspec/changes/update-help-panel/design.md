## Context

說明面板由 `src/view.ts` 的 `buildHelpPanel` 用 DOM 建出，是靜態內容。目前有三區：快捷鍵、圖示說明（五種樣式附色塊）、月視圖（三種文字樣式與 General 列一行）。樣式在 `styles.css` 的 `#help-panel`，固定在右上角，最大寬度 340px，沒有高度上限。

這一輪 0.5.0 新增、但面板沒提到的樣式與操作：
- 暫停列的斜線紋與 `⏳ 暫停` 標籤。
- 已結案的灰色。
- 今天欄的淡紅色。
- 專案名稱旁的 `⚠`。
- General 列的名稱標籤與顏色。
- `還沒排` 的數字與浮窗。
- 年份與月份的 `◀ ▶`、`今年`／`本月`。
- `編輯分類與狀態`。
- 圖例的拖拉與置頂、欄寬拖拉。

其中後兩項其實不是這一輪才有，但面板從來沒寫過。

## Goals / Non-Goals

**Goals:**

- 畫面上看得到的每一種樣式，在面板裡都找得到一行說明，並附上同樣式的小示範。
- 主要操作一行一句。

**Non-Goals:**

- 做成可以搜尋或分頁的說明。
- 動態依資料顯示（面板維持靜態）。

## Decisions

### 四區、一行一個，示範沿用真的樣式類別

- 圖示說明的示範色塊沿用畫面上的類別，所以畫面改了，示範也跟著改：
  - 新增暫停的斜線紋，用一個帶 `status-pending` 外層的小色塊加 `⏳ 暫停` 標籤。
  - 新增已結案的灰色色塊。
  - 新增今天欄的淡紅色小格。
  - 新增 `⚠`。
- 月視圖區沿用既有的文字示範，新增名稱標籤示範（用 `gc-label` 類別與預設藍）與 `還沒排` 數字示範。
- 新增「操作」區：只寫動作與結果，不放示範。

替代方案是另開一份說明頁。朱騏要的是按 `?` 就能對照，所以不採用。

### 面板太長時在面板裡捲動

面板加上最大高度（視窗高度扣掉上下邊距）與內部捲動，避免小視窗時超出畫面。

### 改成分頁與分組（2026-11-20 朱騏回饋）

四區版本上線後，朱騏覺得全部擠在一起很難讀，要求依年視圖與月視圖分頁，並把圖示依抽象程度分組。參考 Nielsen Norman Group 的〈Tabs, Used Right〉與〈Progressive Disclosure〉：
- 分頁適合「不需要同時對照」的內容（看年視圖時用不到月視圖的說明）。
- 標籤一兩個字。
- 最常用的分頁預設打開。
- 被選中的分頁要有兩種以上的標示。
- 分頁裡用小標題分組。
- 不常用的操作與快捷鍵放到次要的位置。

因此：

- 三個分頁：`年視圖`、`月視圖`、`操作`。每次打開面板時，預設選中目前顯示的視圖。
- 被選中的分頁同時用粗體與底線標示；用 `role="tablist"`／`tab`／`tabpanel`，方向鍵可以切換。
- 年視圖依抽象程度分四組：
  - 每一格＝這週的任務（實心、淡色打勾、虛線、空白）。
  - 需要注意（紅色、`⚠`）。
  - 整列＝專案狀態（暫停斜線紋、已結案灰色）。
  - 顏色與欄位（分類色點、今天欄）。
- 月視圖分四組：任務文字、格子底色（一行指回年視圖）、General 列、還沒排。
- 操作分三組：編輯、切換（含快捷鍵 `T`、`M`、`?`）、版面。快捷鍵不再單獨一區，併進「切換」。
- 示範沿用畫面的類別（同前）。

替代方案一：維持單頁、只加小標題。內容一樣長，年與月的說明還是混在一起，所以不採用。

替代方案二：手風琴（可展開的段落）。朱騏指定分頁，而且年、月兩組內容份量相當，分頁更直接，所以不採用。

## Implementation Contract

**行為：** 打開 `?` 面板看到三個分頁，預設選中目前的視圖；每個分頁內依小標題分組，規格列出的每一行都在，示範樣式和畫面一致，面板不超出視窗。

**介面與資料形狀：** 沒有新的設定。

**失敗與錯誤處理：** 無。

**驗收標準：**
- tests/help-panel.test.ts 涵蓋規格的四個情境：預設分頁、切換分頁、年視圖分組、月視圖分組。
- `npm test`、`npm run lint`、`npm run build` 通過。
- 朱騏打開面板確認。

**範圍內：** 說明面板內容、示範樣式、面板捲動。

**範圍外：** Non-Goals 列出的所有項目。
