## Context

儀表板現在只為電腦設計：

- 年視圖：左邊名稱欄固定 280 像素，加上 52 週、每週 32 像素，約 1,950 像素寬。
- 月視圖：表格寬度 100%、`table-layout: fixed`，扣掉名稱欄和 `還沒排` 欄，手機（約 390 像素）上每週只剩 10 像素左右。
- 只有滑鼠能用的操作：圖例拖拉排序、名稱欄拖拉調整寬度（都只聽 mousedown／mousemove）。
- 要滑鼠停在上面才看得到的資訊：⚠ 的原因、按鈕提示。
- 點專案名稱會在右側分割畫面開筆記（`createLeafBySplit`），手機沒有左右分割。
- 行事曆連結存在 Obsidian 的密碼保管，還沒在手機上測過。

程式本身沒有用到 Node 或 Electron：讀行事曆用 Obsidian 的 `requestUrl`，改筆記用 `vault.process`。所以要做的是讓手機用得了畫面，不需要換資料來源。

**第一版與改版的原因**

第一版（0.6.0-beta.1，提交 61f42a6）在手機上畫由上往下的 4 週清單：每週照專案分組列任務、每一行直接放打勾與 `◀` `▶`，最上面一列 `之前還沒做（n）` 收著過期的任務。程式在 `src/core/phone-weeks.ts` 與 `src/phone-week-list.ts`。

朱騏在手機上用過後回饋：「使用上其實好像還是不太好」「有一點沒有太大的意義」，他想看到的是像「月平行互見表」那樣的表。平行互見表是他每週五規劃下週用的 Google 試算表：一列一個專案、一欄一週，格子裡直接寫任務，一眼看出這個月每個專案在動什麼、哪一週會爆。0.4.0 的月視圖就是照這張表做的。週清單把它拆成一長條，看得到「這週要做什麼」，卻看不出「專案之間怎麼平行」，所以改成手機直接用月視圖，拿掉週清單。

可以直接沿用的部分：

- `MonthView`：整張月視圖表格，含格子的顏色、任務文字、今天那週的標示、`還沒排` 數量。
- view 的月份導覽（`◀` `▶` `本月`）、`顯示暫停（n）`、`visibleSortedProjects`。
- 週浮窗與還沒排浮窗（`WeekPopover`），以及 view 給它們的 toggle／shift／schedule／add 處理：寫回筆記、「那一行剛被改過就不寫」的保護、失敗提示、寫完重繪並重新打開浮窗。
- `placePopover`：浮窗的定位算式。
- 第一版已經做好、繼續保留的：用 `Platform.isPhone` 決定版面、手機上不讀行事曆、設定頁的 Calendars 說明、manifest、測試替身與截圖替身的 `Platform`。

介面簡化檢查的四題：

1. **誰、在做什麼事的途中？** 朱騏出門時拿手機，想看這個月每個專案在動什麼、這週和下週要做什麼，做完了順手打勾，排不進來的就往後移。
2. **是主要工作還是附帶的事？** 看整張表是主要工作，所以一打開就是表格，不多放東西在上面。打勾、移週是在格子裡點開浮窗完成，跟電腦一樣，不用重新學。打開筆記是附帶的事，用點專案名稱完成。
3. **能不能併進既有的控制項？** 手機畫面上只保留 `顯示暫停（n）` 與月份導覽，其餘的控制列、圖例、說明面板都不出現。沒有新的按鈕或區塊。
4. **多久用一次？** 每天都可能用，所以打開就是本月的表。

## Goals / Non-Goals

**Goals:**

- 在手機上一打開儀表板，就看到本月的月視圖：一列一個專案、一欄一週、格子裡寫任務。
- 手機直放時一次看到約 2 週，左右滑看其他週；橫放時寬度夠就一次看到整個月。專案名稱一直留在左邊。
- 在手機上用和電腦相同的週浮窗與還沒排浮窗編輯任務。
- 手機上看到的月份、任務與完成狀態，跟電腦上同一個月份完全一致。
- 平板與電腦的畫面、行為完全不變。

**Non-Goals:**

- 手機上的年視圖、年／月切換、Timeline。
- 手機上的行事曆行程（General 列）、`↻`、`Refresh calendars` 指令，以及在手機上設定行事曆連結。
- 手機上改分類與狀態、`顯示已結案`、⚠ 日期提醒、說明面板與 `?` 按鈕、快捷鍵。
- 保留第一版的 4 週清單或 `之前還沒做` 區塊，或讓使用者在清單與月視圖之間切換。
- 只畫顏色與數量、點了才看得到任務的縮圖版月視圖（討論時的方案 B）：看不出每個專案在動什麼，跟平行互見表差太多。
- 手機上自己調整名稱欄寬度、讓圖例拖拉排序支援觸控（平板上這兩項仍需要滑鼠或觸控板，寫進 README）。
- 用視窗寬度切換版面。
- 浮窗改成從畫面底部滑上來的面板。

## Decisions

### 用 Obsidian 的手機判斷決定版面

（第一版已實作，保留。）儀表板分頁打開時讀一次 Obsidian 的 `Platform.isPhone`，存成 view 的 `layout: 'phone' | 'full'`。之後轉向、改變視窗大小都不重新判斷，下次打開分頁時才重讀。測試用的 obsidian 替身（`tests/stubs/obsidian.ts`）與截圖用的替身（`scripts/screenshots/shim/obsidian.ts`）都提供可以改的 `Platform.isPhone`。

替代方案：

- 看視窗寬度：在電腦上把儀表板拉窄，畫面就會突然變成手機版，所以不採用。
- 看 `Platform.isMobile`：這個值包含平板，可是平板放得下電腦版，所以不採用。

### 手機直接畫電腦的月視圖，不另做一套畫面

手機版面用同一個 `MonthView` 物件畫表格，手機與電腦的差別只在三個地方：

- view 給 `MonthView` 的 host：手機上 `calendarRow()` 一律回傳 `null`，所以沒有 General 列；專案列照舊由 `visibleSortedProjects()` 決定（手機上沒有 `顯示已結案`，所以 `showClosed` 永遠是 false）。
- 樣式：全部掛在 `.pd-phone` 底下（見下一節）。
- ⚠ 與分類、狀態選單：`renderProjectHeadCell` 照舊畫出來，手機用樣式藏起來。不另寫一份手機專用的專案欄，避免兩份程式走偏。

view 在手機上的版面：

- `buildLayout` 的手機分支：不畫 header（`專案總覽`、統計、圖例）；控制列只放 `顯示暫停（n）` 與月份導覽 `◀ 標題 ▶ 本月`，不放年／月切換、`顯示已結案`、`編輯分類與狀態`；不建立說明面板與 `?`。月份導覽沿用 `buildScaleControls` 裡導覽那一段的元素與行為，年／月切換鈕在手機上不建立。週浮窗元素、提示框與 `MonthView` 照電腦的方式建立。
- `scale`：手機上固定是 `'month'`，`shownMonth` 在分頁打開時設成 `monthOfDate(today)`；不讀也不寫 `dashboard.scale`，也不寫 `dashboard.viewMode`。
- `registerInteractions` 的手機分支：只註冊週浮窗（點格子、點還沒排、點外面關閉、捲動關閉）與點專案名稱開筆記；不註冊圖例拖拉、名稱欄拖拉欄寬、改分類、改狀態。
- 快捷鍵：手機上照第一版，整組不註冊（`M`、`T`、`?`、`Escape` 都沒有作用；點浮窗外面就能關閉浮窗）。

替代方案：

- 手機另寫一個表格元件：要維護兩份「格子裡寫什麼」的規則，所以不採用。
- 在電腦版的 `buildLayout` 裡用 CSS 把多的東西藏起來：說明面板、圖例的監聽器還是會被建立，快捷鍵也還在，所以只在樣式上藏 ⚠ 與選單這兩個畫在格子裡的東西，其餘在程式裡就不建立。

### 手機的欄寬與左右捲動

樣式全部掛在 `.pd-phone` 底下，電腦與平板沒有 `.pd-phone`，畫面不變：

- 名稱欄：手機上 view 把 `--proj-col-width` 設成 `96px`，不用 `dashboard.projColWidth`；`.resize-handle` 不顯示；名稱欄的左右留白縮小，專案名稱可以換行。
- 週欄：每週至少 120 像素。`table-layout: fixed` 底下，表格寬度會撐到「欄寬加總」與 100% 兩者較大的一個，所以做法是讓 `MonthView` 在表格上記下週數（`data-weeks="5"`，不影響電腦版畫面），`.pd-phone table.month-grid[data-weeks="N"]` 設 `min-width: calc(96px + N × 120px + 48px)`；週欄本身不設寬度，表格比這個寬時由瀏覽器平均分給週欄。一個月份是 4 或 5 週，兩種都要有規則。
- `還沒排` 欄：48 像素。
- 捲動：`.pd-phone #chart` 改成 `overflow-x: auto`，表格在 `#chart` 裡左右捲；名稱欄的 `position: sticky; left: 0` 沿用電腦版，所以左右滑時專案名稱留在左邊。儀表板分頁本身不左右捲。
- 控制列：左右留白縮小，月份標題放不下時可以換行，不切字。
- 點的範圍：`顯示暫停（n）`、`◀`、`▶`、`本月` 至少 44×44 像素。

驗證這幾條要量真的版面，jsdom 量不出來，所以在截圖腳本裡用瀏覽器量：390 與 800 像素寬各量一次名稱欄寬、每欄位置、是否左右捲、捲動後名稱欄位置。

### 手機上的浮窗沿用電腦的浮窗，只調大小

- 週浮窗與還沒排浮窗的內容、按鈕、寫入流程完全沿用電腦版。寫入成功後重繪並重新打開同一個專案、同一週的浮窗，也沿用電腦版的 `refreshPreservingPopover`。
- 浮窗掛在 document body 上，拿不到 `.pd-phone`，所以手機上 view 在浮窗元素加一個手機專用的類別 `pd-popover-phone`，樣式掛在這個類別底下：最寬 `calc(100vw - 16px)`、按鈕與核取方塊的可點範圍至少 44×44 像素。電腦與平板的浮窗不加這個類別，大小與間距不變。
- `placePopover` 加一個可以選的 `margin` 輸入，預設沿用 `POPOVER_MARGIN`（4 像素）；手機上 view 傳 8，浮窗左右邊緣離螢幕至少 8 像素。這是純函式，由 `tests/popover-position.test.ts` 鎖定。
- 左右滑表格時，格子移動了，浮窗照電腦版的規則關閉。

替代方案：手機上把浮窗改成從底部滑上來的面板。要另外寫一套開關與動畫，而且跟電腦的操作不一樣，所以這一版不做。

### 在手機上開啟筆記改用同一個分頁

手機上點專案名稱（名稱欄或浮窗標題）或 `↗`，都先關掉浮窗，再用儀表板自己的分頁打開那則筆記（`this.leaf.openFile`），讓 Obsidian 的返回鍵回到儀表板。`↗` 打開之後照電腦版選取那一行。電腦與平板照舊開在右側分割畫面並重複使用。

儀表板分頁換成筆記之後，儀表板自己的提示框就不在畫面上了。所以手機上筆記打開之後才發生的提示（`↗` 找不到那一行），改用 Obsidian 的 `Notice` 顯示，文字相同。筆記打開之前的提示（筆記不見了），照舊用儀表板的提示框，因為儀表板還在畫面上。

替代方案：開新分頁（`getLeaf('tab')`）。新分頁沒有上一頁，返回鍵回不到儀表板，要從分頁切換器找回來，所以不採用。

### 手機上收起來的功能

手機上不出現：

- header（`專案總覽`、統計、圖例）。
- 年／月切換鈕、`顯示已結案`、`編輯分類與狀態`。
- 說明面板與 `?` 按鈕、⚠、分類與狀態選單。
- 快捷鍵 `M`、`T`、`?`：在手機上什麼都不做（接了外接鍵盤也一樣）。

行事曆（第一版已實作，保留）：

- 手機上不讀行事曆。`CalendarStore` 不開始任何讀取，`Refresh calendars` 指令不註冊，月視圖沒有 General 列。
- 設定頁的 Calendars 區塊在手機上只顯示標題和一句 `Calendar events show on a computer or tablet. Add your calendars there.`，不放任何欄位，也不呼叫 `app.secretStorage`。手機上存其他設定時，`calendars` 原樣保留。

沒有專案資料夾、沒有專案時，照舊顯示電腦版的提示文字（例如 `找不到專案資料夾：<folder>`）。

## Implementation Contract

**可以觀察到的行為：**

- 手機上打開儀表板，由上而下是：
  1. 控制列：`顯示暫停（n）`（n 大於 0 時才有）、`◀ 2026 年 11 月（W45–W49） ▶`（以今天 2026-11-20 為例；`本月` 只在不是本月時出現）。
  2. 月視圖表格：名稱欄 96 像素固定在左邊，週欄至少 120 像素，`還沒排` 欄 48 像素。390 像素寬時看得到名稱欄加 W45、W46 兩整欄，往左滑看到 W49 與 `還沒排`；800 像素寬時 5 週與 `還沒排` 全部看得到，週欄等寬。
- 點格子打開週浮窗、點還沒排數字打開還沒排浮窗，內容與動作跟電腦一樣；浮窗左右離螢幕至少 8 像素，按鈕可點範圍至少 44×44 像素。
- 點專案名稱或 `↗`，筆記開在儀表板的分頁，按返回回到儀表板。
- 平板與電腦的畫面、快捷鍵、行事曆讀取都和 0.5.0 完全相同，10 張電腦版截圖逐位元相同。

**介面與資料形狀：**

- `placePopover(input)` 的輸入多一個可以選的 `margin`（像素），沒給時等於 `POPOVER_MARGIN`；既有呼叫與測試的結果不變。
- `MonthView.render` 在表格元素上記下週數 `data-weeks`（週欄的數量），其他輸出不變。
- 手機上浮窗元素多一個類別 `pd-popover-phone`；手機上 view 把 `--proj-col-width` 設成 `96px`。
- `src/core/phone-weeks.ts` 與 `src/phone-week-list.ts` 不存在。
- `manifest.json`：`isDesktopOnly` 是 `false`，其他欄位不變。

**失敗時：**

- 寫入失敗的提示文字與重新掃描，和電腦版週浮窗完全相同。
- 手機上筆記打開之後的提示改用 Obsidian 的 `Notice`，文字與電腦版相同。
- 手機上 `app.secretStorage` 不存在或會丟錯也不影響，因為手機上從不呼叫它。

**驗收方式：**

- `tests/phone-month-view.test.ts`：在測試替身把 `Platform.isPhone` 設成 true 打開儀表板，涵蓋 dashboard-phone-month-view 的情境（版面、控制列、月份導覽、打開時是本月、已結案不出現、沒有 General 列、快捷鍵沒作用、不寫偏好、浮窗打勾／移週／排進週／被改過的行、手機浮窗類別、開筆記與 `↗` 用儀表板自己的分頁且沒有分割）。由另一段 Codex 對話先寫、主代理確認後鎖定，寫程式的那一段只拿規格與鎖定的測試。
- `tests/popover-position.test.ts`：`margin` 是 8、視窗 390 像素寬時，浮窗左右都離邊緣至少 8 像素；沒給 `margin` 時結果與現在相同。
- `tests/phone-calendar.test.ts` 與其他既有測試全部通過，`npm run lint` 與 `npm run build` 通過。
- 截圖腳本在 390 與 800 像素寬量版面（名稱欄寬、欄位置、捲動後名稱欄位置、浮窗左右邊緣），量不對就失敗；`phone-month-view.png` 逐張目視檢查。
- 朱騏在自己的手機上實測一次：直放、橫放、左右滑、點格子打勾與移週、從還沒排排進週、新增任務、點專案名稱與 `↗` 再按返回。

**範圍：**

- 範圍外：Non-Goals 列出的全部項目；電腦版與平板版的任何行為改變。

## Risks / Trade-offs

- [手機上按返回不一定回到儀表板（儀表板分頁沒有存狀態，回去時是重新打開，月份回到本月）] → 實機測試時確認。回不去的話改成開新分頁，並把 README 的說明改成「從分頁列切回儀表板」。返回後月份會回到本月，不會停在剛才翻到的月份，這一版接受。
- [直放時一次只看得到約 2 週，要左右滑才看得到整個月] → 名稱欄固定在左邊，滑的時候還知道是哪個專案；橫放可以看整個月，README 寫出來。
- [週欄 120 像素時，一格一行約 8 個中文字，任務多的格子會很高] → 文字換行不切字；格子高度跟著內容長，跟電腦版月視圖相同。
- [浮窗在手機上蓋住大半個螢幕] → 浮窗夾在螢幕內，裡面的清單自己捲；點外面就關閉。
- [有些裝置的 `Platform.isPhone` 判斷和使用者想的不同，例如很小的 Android 平板] → 判斷錯時看到的是電腦版畫面，還是可以左右捲動使用，不會壞掉。
- [自動測試跑不了真的手機] → DOM 測試鎖行為、截圖腳本在瀏覽器量版面，最後由朱騏在手機上實測。
- [手機不讀行事曆，同步過去的 `calendars` 設定在手機上沒有作用] → 設定頁在手機上用一句話說明行事曆只在電腦或平板顯示。
- [平板上圖例拖拉排序、名稱欄拖拉調整寬度不能用手指操作，⚠ 原因也看不到] → 這一版不處理，寫進 README 的平板說明。
- [裝過 0.6.0-beta.1 的人會看到畫面從週清單變成月視圖] → 只有朱騏裝過測試版；CHANGELOG 只寫正式版 0.6.0 的手機月視圖。

## Migration Plan

- 先發 0.6.0-beta.2 測試版給朱騏用 BRAT 在手機上試，確認後再發正式版 0.6.0。
- 退回的方法：把 `isDesktopOnly` 改回 `true` 再發一版，電腦版行為不受影響。
