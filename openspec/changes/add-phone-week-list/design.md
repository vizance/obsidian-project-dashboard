## Context

儀表板現在只為電腦設計：

- 年視圖：左邊名稱欄固定 280 像素，加上 52 週、每週 32 像素，約 1,950 像素寬。
- 月視圖：表格寬度 100%，扣掉名稱欄和 `還沒排` 欄，手機（約 390 像素）上每週只剩 10 像素左右。
- 只有滑鼠能用的操作：圖例拖拉排序、名稱欄拖拉調整寬度（都只聽 mousedown／mousemove）。
- 要滑鼠停在上面才看得到的資訊：⚠ 的原因、按鈕提示。
- 點專案名稱會在右側分割畫面開筆記（`createLeafBySplit`），手機沒有左右分割。
- 行事曆連結存在 Obsidian 的密碼保管，還沒在手機上測過。

程式本身沒有用到 Node 或 Electron：讀行事曆用 Obsidian 的 `requestUrl`，改筆記用 `vault.process`。所以要做的是換一個手機用得了的畫面，不需要換資料來源。

可以直接沿用的計算：

- `taskLinesForWeek`：照週六規則把任務行歸到週。
- `isoWeekOfDate`、`mondayOfWeek`、`weekRangeShort`、`monthDayLabel`：週與日期的標示。
- `visibleProjects`、`sortProjects`：儀表板的列與順序，由 view 的 `visibleSortedProjects` 組合。
- `scheduleDateForWeek`：排進某週時寫哪一天。
- `TaskWriter` 的 `toggle` 與 `shift`：寫回筆記，含「那一行剛被改過就不寫」的保護。
- view 給週浮窗用的 toggle／shift 處理：失敗時的提示文字與重新掃描。

介面簡化檢查的四題：

1. **誰、在做什麼事的途中？** 朱騏出門時拿手機，想知道這週和接下來幾週要做什麼，做完了順手打勾，排不進來的就往後移。
2. **是主要工作還是附帶的事？** 看清單是主要工作。打勾、移一週是主要工作的一部分，所以放在每一行上。打開筆記是附帶的事，用點專案名稱完成，不另外放按鈕。
3. **能不能併進既有的控制項？** 手機畫面上只保留 `顯示暫停（n）`，其餘的控制列、圖例、說明面板都不出現。`之前還沒做` 用一列可展開的標題，不多放按鈕。
4. **多久用一次？** 每天都可能用，所以清單一打開就看得到。過期的任務收起來，但一直留著數量。

## Goals / Non-Goals

**Goals:**

- 在手機上一打開儀表板，就看到本週和後面 3 週每個專案要做的任務。
- 在手機上打勾或取消、把任務移一週，週已經過了的任務可以一鍵排到本週。
- 手機上看到的週、任務與完成狀態，跟電腦上月視圖同一週的格子完全一致。
- 平板與電腦的畫面、行為完全不變。

**Non-Goals:**

- 手機上的年視圖、月視圖、Timeline。
- 手機上的行事曆行程（General 列）、`↻`、`Refresh calendars` 指令，以及在手機上設定行事曆連結。
- 手機上改分類與狀態、`顯示已結案`、⚠ 日期提醒、說明面板與 `?` 按鈕、快捷鍵。
- 手機上新增任務、把 `還沒排` 的任務排進某週。
- 可以自己選要看幾週、往前或往後翻週。
- 讓圖例拖拉排序、名稱欄拖拉調整寬度支援觸控（平板上這兩項仍需要滑鼠或觸控板，寫進 README）。
- 用視窗寬度切換版面。

## Decisions

### 用 Obsidian 的手機判斷決定版面

儀表板分頁打開時讀一次 Obsidian 的 `Platform.isPhone`。是手機就畫手機週清單，不是就照舊畫年視圖或月視圖。之後轉向、改變視窗大小都不重新判斷，下次打開分頁時才重讀。

為了測試，view 不直接散用 `Platform`，而是在分頁打開時把結果存成一個欄位，例如 `layout: 'phone' | 'full'`。測試用的 obsidian 替身（`tests/stubs/obsidian.ts`）與截圖用的替身（`scripts/screenshots/shim/obsidian.ts`）都提供可以改的 `Platform.isPhone`。

替代方案：

- 看視窗寬度：在電腦上把儀表板拉窄，畫面就會突然變成週清單，所以不採用。
- 看 `Platform.isMobile`：這個值包含平板，可是平板放得下月視圖，所以不採用。

### 手機週清單沿用月視圖的週與任務計算

新增一個純計算模組 `src/core/phone-weeks.ts`，不碰畫面也不碰 Obsidian：

- `phoneWeekLabels(today)`：回傳 4 個 ISO 週標籤。第一個是 `isoWeekOfDate(today)`，也就是今天所在的週一到週日（和月視圖標示今天的規則相同，不套週六規則）；後面 3 個是它的週一各加 7、14、21 天所在的週，跨年也照算。
- `phoneWeekGroups(projects, weekLabels, rules)`：每一週列出「專案 → 那週的任務行」。專案順序就是傳進來的順序（view 傳 `visibleSortedProjects()`）。任務行用 `taskLinesForWeek` 取得，順序與週浮窗相同。那週沒有任務的專案不列。
- `overdueLines(projects, rules, today)`：找出「週已經過了還沒做」的任務行。條件是有核取方塊、還沒完成、`due` 不是 null，而且 `weekOfTaskDate(due, rules)` 那週的週一，比今天所在週的週一早。照專案順序分組，同一專案內依 `due` 排，`due` 相同時依行號。
- `scheduleToThisWeekDays(line, rules, today)`：回傳「排到本週」要移動的天數，也就是 `scheduleDateForWeek(本週, rules)` 減去 `line.due`。

每一行直接帶 `TaskLine`（含 `raw`、`line`、`checkbox`、`done`、`recurring`、`due`），寫入時才對得回筆記的同一行。4 週都是本週或之後，所以週區塊裡的任務不會是紅色；紅色只出現在 `之前還沒做`。

依介面深度檢查：

- 分界放在 `src/core/phone-weeks.ts`（計算）與 `src/phone-week-list.ts`（畫面）。
- 只有一個轉接層：view 實作畫面需要的 host 介面，做法和 `MonthViewHost` 一樣。
- 計算模組裡有跨年的週、週六規則、過期判斷與排到本週的天數，有實際內容。
- 刪掉計算模組的話，這些規則就得寫進畫面程式，單元測試也沒有純函式可以測。

替代方案：直接把 `monthCellLines` 的結果拿來畫。它只回傳文字與狀態，沒有編輯需要的 `raw` 與 `recurring`，而且它的「逾期」是以格子為單位，不是以單一任務為單位，所以只沿用它底下的 `taskLinesForWeek`。

### 每一行的編輯按鈕沿用週浮窗的規則與寫入路徑

手機週清單由 `src/phone-week-list.ts` 的 `PhoneWeekList` 畫出來，做法比照 `MonthView`：

- 它是獨立元件，只負責畫進容器。
- 編輯動作透過 host 交給 view，view 再用和週浮窗相同的 toggle／shift 處理寫回筆記。

規則與週浮窗一致：

- 核取方塊：每一行都有。有核取方塊、而且不是重複任務的行才能按；重複任務的行不能按，提示文字與週浮窗相同（`重複任務請在筆記裡勾選`）。
- `◀` `▶`：只出現在「有核取方塊、還沒完成、有 `due`」的行，移動 `SHIFT_WEEK_DAYS`（7 天）。
- 一行在寫入時，那一行的按鈕先停用，寫完才恢復。
- 失敗時（筆記不見、那一行剛被改過），提示文字與重新掃描和週浮窗相同。

「排到本週」用 `shift` 寫入，移動天數由 `scheduleToThisWeekDays` 算出來。不用 `schedule`，因為 `scheduleLine` 會在行尾再加一個 `📅`，同一行就有兩個日期。

### 移出 4 週時用提示說明任務去哪了

`◀` `▶` 寫入成功後，用新的 `📅` 日期照週六規則算出它在哪一週：

- 落在本週之前：顯示提示 `已移到 <M/D>，在「之前還沒做」裡`。
- 落在第 4 週之後：顯示提示 `已移到 <M/D>，超出這 4 週`。
- 還在這 4 週裡：不顯示提示，因為任務就在畫面上。

提示沿用 view 既有的提示框（`showToast`）。這樣任務從畫面消失時，使用者知道它去了哪裡，要改回來也找得到。

### 之前還沒做區塊收著過期的任務

- 清單最上面一列是標題 `之前還沒做（n）`，n 是 `overdueLines` 的數量。收起時前面是 `▸`，展開時是 `▾`。點整列切換。
- 每次打開分頁都是收起的。重繪時（例如筆記改了）保留展開或收起的狀態與捲動位置。
- 展開後照專案分組。每行是紅色文字、`M/D` 日期、核取方塊，以及一顆 `排到本週`；這一區不放 `◀` `▶`。
- 在這一區打勾的行，會留在原位顯示成灰色、打勾，直到收起這一區或重新打開分頁。這樣按錯了可以當場取消。n 只算還沒完成的行。
- 收起時 n 是 0，整列不出現。展開時 n 變成 0，標題照樣留著（顯示 `之前還沒做（0）`），收起後才消失。

### 在手機上開啟筆記改用同一個分頁

手機上點專案名稱，用儀表板自己的分頁打開那則筆記（`this.leaf.openFile`），讓 Obsidian 的返回鍵回到儀表板。電腦與平板照舊開在右側分割畫面並重複使用。

替代方案：開新分頁（`getLeaf('tab')`）。新分頁沒有上一頁，返回鍵回不到儀表板，要從分頁切換器找回來，所以不採用。

### 手機上收起來的功能

手機上不出現：

- 控制列。只保留 `顯示暫停（n）`，規則與電腦相同：n 大於 0 才出現，分頁打開時是不勾的。
- 年／月切換鈕、年份與月份導覽、`顯示已結案`、`編輯分類與狀態`。
- 圖例、說明面板與 `?` 按鈕、⚠。
- 快捷鍵 `M`、`T`、`?`：在手機上什麼都不做（接了外接鍵盤也一樣）。

行事曆：

- 手機上不讀行事曆。`CalendarStore` 不開始任何讀取，`Refresh calendars` 指令不註冊。
- 設定頁的 Calendars 區塊在手機上只顯示標題和一句 `Calendar events show on a computer or tablet. Add your calendars there.`，不放任何欄位，也不呼叫 `app.secretStorage`。手機上存其他設定時，`calendars` 原樣保留。

沒有專案資料夾、沒有專案時，照舊顯示電腦版的提示文字（例如 `找不到專案資料夾：<folder>`）。

### 手機版面的樣式與觸控大小

- 手機版面的樣式放在 `styles.css`，全部掛在一個手機專用的外層類別底下，例如 `.pd-phone`，不影響電腦版。
- 沿用既有的顏色變數：灰字、警示紅、分類色點。
- 核取方塊、`◀` `▶`、`排到本週`、`之前還沒做` 標題列、專案名稱，可以點的範圍都至少 44×44 CSS 像素。
- 任務文字可以換行，不能被切掉。

### README 與截圖加上手機版

- 兩種語言的 README 都加一節手機版，放在「暫停的專案與狀態」之後、「設定」之前，附一張手機週清單截圖。
- 安裝段落把「Desktop only」改成「電腦、平板、手機都能用」。並寫明平板用的是電腦版畫面，圖例拖拉排序與名稱欄拖拉調整寬度需要滑鼠或觸控板。
- `docs/details.md` 與 `docs/details.zh-TW.md` 補上手機版的細節規則：哪 4 週、過期的定義、排到本週寫哪一天、移出 4 週時的提示。
- 截圖腳本加一張 `phone-week-list.png`：畫布寬 390 像素，用截圖替身把 `Platform.isPhone` 設成 true，用範例資料，展開 `之前還沒做`。
- CHANGELOG 加一段 0.6.0 的英文與中文說明。

## Implementation Contract

**可以觀察到的行為：**

- 手機上打開儀表板，看到的由上而下依序是：
  1. `顯示暫停（n）`（n 大於 0 時才有）。
  2. `之前還沒做（n）`（有過期任務時才有）。
  3. 4 個週區塊，標題依序是 `本週 W47 11/16–11/22`、`下週 W48 11/23–11/29`、`W49 11/30–12/6`、`W50 12/7–12/13`（以今天 2026-11-20 為例）。
- 週區塊裡，每個專案一組，組標題是分類色點加專案名稱，下面是任務行。每行有核取方塊、任務文字、`M/D`，以及符合條件時的 `◀` `▶`。
- 平板與電腦的畫面、快捷鍵、行事曆讀取都和 0.5.0 完全相同。

**介面與資料形狀：**

- `src/core/phone-weeks.ts` 匯出 `phoneWeekLabels`、`phoneWeekGroups`、`overdueLines`、`scheduleToThisWeekDays`，輸入是 `ProjectRecord[]`、`WeekRules` 或 `ScheduleRules`、今天的 ISO 日期字串，輸出只含週標籤、`ProjectRecord` 與 `TaskLine`（形狀為 `PhoneWeek { week, groups }` 與 `PhoneProjectLines { project, lines }`，由 tests/phone-weeks.test.ts 鎖定）。
- `src/phone-week-list.ts` 匯出 `PhoneWeekList` 與它的 host 介面。host 提供列、設定、今天、toggle、shift、開筆記；`PhoneWeekList` 從不直接改筆記。
- `manifest.json`：`isDesktopOnly` 是 `false`，其他欄位不變。

**失敗時：**

- 寫入失敗的提示文字與重新掃描，和週浮窗完全相同。
- 手機上 `app.secretStorage` 不存在或會丟錯也不影響，因為手機上從不呼叫它。

**驗收方式：**

- `tests/phone-weeks.test.ts`：跨年的 4 週、週六規則、過期判斷、排到本週的天數（含「寫星期六且週六規則開啟」）、專案順序與暫停專案。
- `tests/phone-week-list.test.ts`：在測試替身把 `Platform.isPhone` 設成 true，打開儀表板，檢查區塊順序、`這週沒有任務`、按鈕出現的條件、打勾與移一週寫回筆記的內容、提示文字、`之前還沒做` 的展開與保留規則、手機上沒有年／月切換與說明面板、沒有任何 `requestUrl` 呼叫。
- 既有測試全部通過，`npm run lint` 與 `npm run build` 通過。
- 截圖 `docs/images/phone-week-list.png` 逐張目視檢查。
- 朱騏在自己的手機上實測一次：開清單、打勾、移一週、排到本週、點專案名稱再按返回。

**範圍：**

- 範圍內：上面列的手機畫面、manifest、手機上的行事曆與設定頁行為、README、details、CHANGELOG、截圖。
- 範圍外：Non-Goals 列出的全部項目；電腦版與平板版的任何行為改變。

## Risks / Trade-offs

- [手機上按返回不一定回到儀表板（儀表板分頁沒有存狀態，回去時是重新打開）] → 實機測試時確認。回不去的話改成開新分頁，並把 README 的說明改成「從分頁列切回儀表板」。
- [有些裝置的 `Platform.isPhone` 判斷和使用者想的不同，例如很小的 Android 平板] → 判斷錯時看到的是電腦版畫面，還是可以左右捲動使用，不會壞掉。
- [自動測試跑不了真的手機] → 純計算用單元測試，畫面用 DOM 測試加 390 像素寬的截圖，最後由朱騏在手機上實測。
- [手機不讀行事曆，同步過去的 `calendars` 設定在手機上沒有作用] → 設定頁在手機上用一句話說明行事曆只在電腦或平板顯示。
- [平板上圖例拖拉排序、名稱欄拖拉調整寬度不能用手指操作，⚠ 原因也看不到] → 這一版不處理，寫進 README 的平板說明。
- [`之前還沒做` 可能累積很多舊任務] → 預設收起，只留數量；展開後照專案分組，可以一鍵排到本週或直接打勾。

## Migration Plan

- 發布為 0.6.0。手機上可以用 BRAT 安裝，或透過 Obsidian Sync 同步外掛。
- 退回的方法：把 `isDesktopOnly` 改回 `true` 再發一版，電腦版行為不受影響。
