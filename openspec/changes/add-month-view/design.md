## Context

儀表板目前只有年視圖：一列一個專案、一欄一個 ISO 週，格子只畫顏色（solid、settled、overflow、dashed、blank），要看那週排了什麼得點開週浮窗。朱騏每週五規劃下週時用的是 Google 試算表的月平行互見表，一個月 4～5 週，格子裡直接寫任務。他的表格用「週一落在哪個月」分月份：10 月是 W41～W44、11 月是 W45～W49。年視圖的表頭則是在 `buildWeeks`（`src/core/weeks.ts`）裡用「週四落在哪個月」分，所以 2026 年有五週對不上（另外 W01 的週一在前一年，另訂例外）。

這次要用的既有元件：

- 週浮窗（`src/week-popover.ts`）已經能編輯任務。
- `taskLinesForWeek` 照目前設定（含週六規則）列出某週的任務行，`unscheduledTasks` 列出還沒排日期的任務。
- `perWeekCells` 算出每一週的格子種類。

`src/view.ts` 已經超過一千行。

## Goals / Non-Goals

**Goals:**

- 在同一個儀表板分頁切換年視圖與月視圖，月視圖格子直接列出任務，點格子用週浮窗編輯。
- 年視圖與月視圖對「某週屬於哪個月、哪一季」的判斷完全一致，並和朱騏的試算表一致。
- 月視圖的任務、狀態、格子種類都來自既有的純函式，不另寫一套週對應。

**Non-Goals:**

- 行事曆列、番茄鐘、常態列、`>` 延後痕跡、拖曳換週。
- 在格子裡直接打字或勾選。
- 「還沒排」欄可以點擊或直接排程。
- timeline 模式套用到月視圖。

## Decisions

### 週的月份：週一規則，W01 永遠算一月

新增 `src/core/months.ts`（不 import obsidian），提供：

- 某週屬於哪一年哪一月
- 某月有哪幾週
- 上一個月、下一個月
- 今天這週屬於哪個月
- 月視圖標題

規則是「週一落在哪個月就屬於哪個月」，只有 W01 例外，永遠屬於它那個 ISO 年的一月。一年最後一週的週一一定在 12 月（介於 12/22 到 12/28），所以只有 W01 的週一可能落在前一年。`buildWeeks` 的月份與季改用這個規則，年視圖的月份、季度表頭和分隔線就跟著一起變。

替代方案一：年視圖繼續用週四規則。這樣年視圖和月視圖對同一週的月份說法不同，也和朱騏的表格不同，所以不採用。

替代方案二：W01 也嚴格照週一規則。2026 年的年視圖會以一週的「12 月、Q4」開頭，所以不採用。

### 月視圖獨立成元件

新增 `src/month-view.ts`，跟週浮窗一樣是獨立元件，負責畫月視圖的表格：表頭、週欄、格子、「還沒排」欄。月視圖用 `weeksOfMonth` 自己算出那個月的週（`WeekInfo[]`），不依賴年視圖只有今年的 `this.weeks`，所以可以切到任何一年的月份。

`src/view.ts` 只負責：

- 決定畫年視圖還是月視圖
- 管理目前顯示的月份
- 把專案資料、目前設定、今天日期交給月視圖
- 處理點格子開浮窗

月視圖透過 host 介面回呼 view，不直接改筆記。

替代方案是在 `renderChart` 裡加分支。主畫面已經一千行，混在一起很難測，也很難維護，所以不採用。

### 格子內容與狀態用純函式算

`src/core/months.ts` 提供兩個純函式：

- 某專案某週的任務行與狀態（`done`、`overdue`、`open`）。任務行與順序直接用 `taskLinesForWeek` 的結果。
- 某專案「還沒排」的數量與提示文字，用 `unscheduledTasks`。

「逾期」的定義是：任務行還沒完成，而且它所在的週比今天這週早。沒有核取方塊的日期行也一樣算，因為它同樣沒有被標成完成。

格子種類用 `perWeekCells` 對月視圖那幾週計算。年視圖畫成一條 `span-dashed` 的那一段，月視圖拆成每週一格 `dashed`；這個拆法做成 `src/core/cells.ts` 的純函式。

### 浮窗沿用，錨點換成月視圖的格子

週浮窗本身完全沿用，但 `src/view.ts` 裡找格子、開浮窗的幾個函式目前都是照年視圖寫的：

- 用 `.bar` 判斷點到哪裡。
- 用 `td.week-cell` 和 `this.weeks`（只有今年的週）找錨點。
- 在 timeline 模式下改成唯讀或直接關掉浮窗。

這些函式要改成依「目前顯示的是年視圖還是月視圖」分開處理，包括：

- `handleBarClick`、`weekOfBarClick`、`anchorForWeek`
- `findWeekBar`、`reopenWeekPopover`

月視圖的部分：

- 格子用自己的類別 `td.month-cell`，帶 `data-path`、`data-week` 和格子種類。
- 找格子用月視圖自己的週列表。
- 不看 `dashboard.viewMode`。
- `overflow` 的格子跟年視圖一樣，把預計結束日期交給浮窗標題。

能不能開浮窗依格子種類：`blank` 不能開，其他可以，和年視圖一致。切換月份或切換年／月時，原本的錨點格子會消失，所以一律關掉浮窗。

### 年／月切換與月份導覽

- 控制列多一組「年／月」切換，按 `M` 也能切換。
- 月視圖時多出 `◀`、月份標題、`▶`、`本月`。
- 年／月的選擇存在 `dashboard.scale`（年視圖或月視圖），由 `src/core/prefs.ts` 的檢查函式處理。顯示哪個月只放在記憶體，每次進月視圖都回到今天這週所屬的月份。
- `T` 只作用在年視圖；月視圖時按 `T` 不改任何東西。

### 版面

- 月視圖用表格，專案欄沿用可拖拉的寬度。
- 週欄用自己的類別（`th.month-week`、`td.month-cell`），平分剩下的寬度，月視圖不用橫向捲動；年視圖 32px 固定週寬的規則只套用在年視圖。
- 週數不補零（`W1`，和年視圖表頭一樣），標題也一樣。
- 今天這週在顯示的月份裡才標示，切到別的月份時不標示任何欄。
- 「還沒排」欄是固定的窄欄。
- 格子高度隨任務行數增加，長文字自動換行。
- 今天這週的欄位比照年視圖標示。
- 所有尺寸與顏色用 `styles.css` 的類別與 CSS 變數，不寫行內樣式。

### 說明面板

靜態說明面板的快捷鍵區加上 `M`，再新增一個月視圖區塊，說明三種文字樣式（打勾灰字、紅字、一般文字）。

### 版本

月視圖是新功能，版本升為 0.4.0。CHANGELOG 寫明年視圖表頭有五週換了月份（W14、W27、W36、W40、W49 各往前一個月；W01 照舊算一月），其中 W14、W27、W40 也跟著換了季（分別從 Q2、Q3、Q4 往前一季），並說明原因。

## Implementation Contract

**行為：**

- 控制列有「年／月」切換；月視圖顯示今天這週所屬的月份，可以切上一個月、下一個月、回到本月；`M` 切換、`T` 在月視圖不作用；重開 Obsidian 後回到上次的年或月視圖，但月份回到本月。
- 年視圖與月視圖對週的月份和季一致：週一規則，W01 算一月；兩份規格表格的每一列都要成立。
- 月視圖欄位：專案、各週（`W44`、`10/26–11/1`）、`還沒排`。列與年視圖相同。
- 格子文字：
  - 完成：`✓` 加灰字。
  - 逾期：紅字。
  - 其他：一般文字。
  - 格子底色依年視圖同一週的格子種類。
- 點格子：非 `blank` 的格子打開週浮窗，錨點在那一格；編輯後月視圖原地重繪，浮窗留在同一週；重繪時月份不變。
- 「還沒排」欄：顯示數量，0 時空白；滑過去的提示一行一個任務；點了沒有反應。

**介面與資料形狀：**

- `src/core/months.ts`：
  - `monthOfWeek(weekLabel) → { year, month }`
  - `weeksOfMonth(year, month) → WeekInfo[]`
  - `shiftMonth({ year, month }, delta)`
  - `monthOfDate(date) → { year, month }`（取該日期所在週的月份）
  - `monthTitle(year, month, weeks)`
  - `monthCellLines(project, weekLabel, settings, today) → { line, text, state }[]`
  - `unscheduledSummary(project) → { count, tooltip }`
- `src/core/cells.ts`：月視圖用的每週格子種類函式，把 `span-dashed` 拆成每週 `dashed`。
- `src/core/prefs.ts`：`parseScale(raw) → 'year' | 'month'`。
- `src/month-view.ts`：獨立元件，透過 host 介面取得資料，回呼點擊格子。

**失敗與錯誤處理：**

- `dashboard.scale` 讀寫失敗或值無效時用 `year`，不中斷畫面。
- 月視圖沒有任何專案列時，顯示與年視圖相同的空狀態。

**驗收標準：**

- 測試：規格的每個範例表格逐列有測試（週與月的對照、2026 年表頭、任務行狀態、偏好檢查），「還沒排」數量與提示情境也有測試。
- 用維護者 vault 的真實筆記比對：月視圖每一格列出的任務，和年視圖同一週的浮窗內容相同。
- 手動驗收：朱騏在 Obsidian 逐項確認。

**範圍內：** 月份規則、年視圖表頭跟著改、月視圖元件、年／月切換與導覽、`M` 快捷鍵、說明面板、偏好、文件與版本。

**範圍外：** Non-Goals 列出的所有項目。

## Risks / Trade-offs

- [年視圖表頭有五週換了月份，朱騏可能以為畫錯] → CHANGELOG 和名詞表寫明規則與原因，手動驗收時特別看 W40。
- [專案多時，月視圖的格子文字很長，表格變得很高] → 先讓格子自動換行、隨內容長高；真的太長再另外討論要不要截斷。
- [月視圖與年視圖各畫一套格子，重繪後重新打開浮窗時找錯格子] → 找格子的函式依目前顯示的視圖分開處理；這一點列入手動驗收。
- [timeline 模式存著的時候切到月視圖，點格子被當成 timeline 處理] → 月視圖的點擊與重新開浮窗不看 `dashboard.viewMode`。
- [現有規格寫死「控制列只有勾選框」「週欄固定 32px」「timeline 模式下浮窗唯讀」，加了月視圖後互相矛盾] → 這次一併修改這幾條規格，限定在年視圖。
- [`M` 和其他外掛的快捷鍵衝突] → 跟 `T` 一樣，只在儀表板是作用中分頁、沒有修飾鍵、焦點不在輸入框時才作用。

## Migration Plan

沒有資料要搬：偏好多一個鍵，缺少時預設年視圖。部署後重新載入外掛即可。回退：重新安裝 0.3.0 的 release 檔案；0.3.0 會忽略 `dashboard.scale`。
