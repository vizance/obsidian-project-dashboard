## Context

專案狀態目前只看檔名開頭的符號（`src/core/scan.ts` 的 `detectStatus`：前三個字元裡的 ⏳／🚧／✅／❌，沒有符號算進行中）。`visibleProjects`（`src/core/cells.ts`）只用「顯示已結案」過濾完成與取消，暫停照常顯示。手動指定的分類存在外掛資料的 `categoryOverrides`，鍵是去掉狀態符號後的名稱（`stripStatus`），所以改狀態符號不會讓分類掉。「編輯分類」勾選框只用 CSS 類別 `editing-categories` 顯示或隱藏每列的 `.cat-select`，不重繪。筆記改名時 `VaultSource` 的 rename 事件會觸發重新掃描。

## Goals / Non-Goals

**Goals:**

- 暫停的專案預設不佔版面，但數量一直看得到，不會被忘掉。
- 在儀表板上就能改專案狀態，改法跟朱騏現在手動改檔名完全一樣，只是不用切出去。

**Non-Goals:**

- 改用 frontmatter 或外掛資料記錄狀態。
- 記住勾選框狀態。
- 批次改狀態。
- 改成完成時自動填實際結束日期。

## Decisions

### 暫停的專案藏在自己的勾選框後面，數量一直顯示

`visibleProjects` 多一個參數 `showPaused`。`view.ts` 在「顯示已結案」旁邊加一個勾選框 `顯示暫停（<n>）`：

- `<n>` 是勾起來時會多出來的暫停專案數。
- `<n>` 是 0 時整個勾選框不出現（介面簡化檢查：用得到才出現）。
- 每次重新掃描都更新數字；分頁打開時一律不勾，跟「顯示已結案」一樣。

暫停的列加類別 `status-pending`。2026-11-20 朱騏要求暫停的列要一眼就看得出來，所以：

- 專案名稱後面加灰色小標籤 `⏳ 暫停`。
- 年視圖色條與月視圖格子改用分類色的斜線紋，不透明度約 0.6。

這樣和進行中（實心全彩）、已結案（灰階 0.35）都分得出來。斜線紋用 CSS 的 `repeating-linear-gradient` 搭配既有的 `--pd-cat-color`，不寫行內樣式。年視圖與月視圖共用 `visibleSortedProjects`，所以兩邊一起生效。

替代方案一：併進「顯示已結案」。暫停不是結束，混在一起會讓「已結案」的意思變模糊，所以不採用。

替代方案二：用設定頁的 `Projects to skip` 藏。那是名稱比對，藏起來畫面上完全沒有提醒，最容易漏掉，所以不採用。

### 狀態選單放進既有的編輯模式，改法就是改檔名開頭的符號

「編輯分類」改名為 `編輯分類與狀態`，同一個 CSS 類別多控制 `.status-select`，平常畫面不變。

- 狀態選單在 `src/project-column.ts` 跟分類選單一起畫，年視圖與月視圖共用。
- 新檔名的算法寫成 `src/core/scan.ts` 的純函式，例如 `filenameWithStatus(filename, status)`：
  - 只換檔名前三個字元裡的那個狀態符號，連同後面的空白，換成新符號加一個空白；沒有就在前面加上。
  - 檔名中間的狀態符號不動。
  - 用規格的範例表鎖住。
- 改名用 `app.fileManager.renameFile(file, newPath)`，Obsidian 會照使用者的設定更新其他筆記的連結；不用 `vault.rename`，它不會更新連結。
- 改名前用 `vault.getAbstractFileByPath(newPath)` 檢查同名：有就不改、顯示 `已經有同名的筆記，狀態沒有改`、選單回到原狀態。筆記不存在就用既有的「找不到筆記」提示。
- 改名成功後不自己重繪，等 rename 事件觸發的重新掃描，和改分類、改任務的回饋方式一致。

替代方案一：狀態存進 frontmatter。和朱騏現有的檔名符號習慣、Obsidian 檔案列表的辨識方式不一致，掃描也要多讀一個來源，所以不採用。

替代方案二：在專案名稱上按右鍵開選單。不好發現，所以不採用。

## Implementation Contract

**行為：**

- 暫停的專案預設隱藏。有暫停專案時出現 `顯示暫停（<n>）`，勾起來就顯示，畫面較淡。
- `編輯分類與狀態` 勾起來時，每列多一個狀態選單；選了就改檔名開頭的符號，連結照 Obsidian 設定更新，分類保留。
- 遇到同名衝突不改名並提示。

**介面與資料形狀：**

- `visibleProjects(projects, showClosed, showPaused)`。
- `src/core/scan.ts` 的新檔名純函式。
- `src/project-column.ts` 的狀態選單。
- 沒有新的設定或外掛資料。

**失敗與錯誤處理：**

- 同名：不改，提示 `已經有同名的筆記，狀態沒有改`。
- 筆記不見：用既有的找不到筆記提示。
- 改名丟出錯誤：顯示 `狀態沒有改，請再試一次`，選單回到原狀態。

**驗收標準：**

- 測試：
  - 新檔名範例表四列。
  - `visibleProjects` 在 `showPaused` 開／關下的結果。
  - 規格「Paused projects are hidden with a count」的數量（13／15、`（2）`）。
  - 既有的 closed 測試改成新的列數（13／20）。
- `npm test`、`npm run lint`、`npm run build` 通過。
- 朱騏手動驗收：
  - 暫停專案隱藏，數量正確。
  - 在儀表板把一個專案改成暫停再改回來，檔名、連結、分類都正確。

**範圍內：** 暫停的過濾與樣式、`顯示暫停（<n>）`、編輯模式的狀態選單與改名、文件。

**範圍外：** Non-Goals 列出的所有項目。

## Risks / Trade-offs

- [改名會動到朱騏的筆記與其他筆記的連結] → 一律透過 `fileManager.renameFile`，連結照 Obsidian 設定處理；只換開頭的符號；同名不改。手動驗收時實際改一次再改回來。
- [Obsidian 的「自動更新內部連結」若沒開，舊連結會斷] → README 註明改名的連結行為取決於 Obsidian 的這個設定，和手動改檔名相同。
- [暫停的專案藏起來後被遺忘] → 數量常駐在控制列，有暫停的專案就看得到。
